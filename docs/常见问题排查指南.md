# MedKB-AI 常见问题排查指南

> 版本: v1.0 | 更新日期: 2025-05-29

---

## 环境与安装

### Q1: pip install 报错 "No matching distribution found for anthropic"
**原因**：Python版本过低。

**解决**：
```bash
python --version  # 确认版本 >= 3.10
# 如果版本低于3.10，请升级Python
# 推荐使用pyenv管理Python版本
```

### Q2: 提示 "ModuleNotFoundError: No module named 'xxx'"
**原因**：依赖未安装或虚拟环境未激活。

**解决**：
```bash
# 确认在虚拟环境中
# Windows: venv\Scripts\activate
# macOS/Linux: source venv/bin/activate

# 重新安装依赖
pip install -r requirements.txt
```

### Q3: Windows下中文输出乱码
**原因**：终端编码问题。

**解决**：
```bash
# PowerShell中执行
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$env:PYTHONIOENCODING = "utf-8"

# 或在CMD中
chcp 65001
set PYTHONIOENCODING=utf-8
```

## 语料采集

### Q4: scraper.py 报 "FileNotFoundError: data/raw/..."
**原因**：data目录结构不完整。

**解决**：
```bash
# 手动创建目录
mkdir -p data/raw data/cleaned data/annotated
python src/scraper.py
```

### Q5: 采集后语料内容为空
**原因**：如果使用了外部源(--source pubmed/nmpa)，API可能不可用。

**解决**：使用内置样本数据（默认模式）
```bash
python src/scraper.py  # 不带任何参数，默认使用样本数据
```

## LLM标注

### Q6: annotator.py 提示 "API key not found"
**原因**：未设置API Key。

**解决方案A（使用Mock模式）**：
```bash
python src/annotator.py  # 默认就是mock模式，无需API Key
```

**解决方案B（使用真实API）**：
```bash
# Claude API
export ANTHROPIC_API_KEY="sk-ant-xxx"
python src/annotator.py --model claude

# GPT API
export OPENAI_API_KEY="sk-xxx"
python src/annotator.py --model gpt
```

### Q7: LLM标注结果质量差，实体识别不准确
**可能原因**：
1. 使用了Mock模式（基于规则匹配，覆盖有限）
2. 文本质量差（含大量噪声）
3. Prompt策略不适合当前文本

**解决**：
```bash
# 1. 切换为真实API
python src/annotator.py --model claude --api-key "your-key"

# 2. 确保文本已经过清洗
python src/cleaner.py

# 3. 尝试不同策略
python src/annotator.py --strategy structured_json  # 推荐
python src/annotator.py --strategy cot              # 复杂文本
```

### Q8: LLM返回JSON解析失败
**原因**：模型输出格式不符合JSON规范。

**解决**：
1. 使用结构化JSON策略（推荐）
2. 增加max_tokens避免截断
3. 在Prompt中强调"只输出JSON"

## 知识库构建

### Q9: kb_builder.py 报 "no such table: drugs"
**原因**：数据库未初始化Schema。

**解决**：
```bash
# 确认db/schema.sql存在
ls db/schema.sql
# kb_builder会自动运行init_schema()
```

### Q10: 知识库中药品/疾病有重复条目
**原因**：
1. 同一实体的不同名称未做对齐
2. 多次运行构建脚本未清理旧数据

**解决**：
```bash
# 运行质量校验检测重复
python src/validator.py --db db/medkb.db --report

# 如需重置知识库
rm db/medkb.db
python src/kb_builder.py --from-structured
```

### Q11: "FOREIGN KEY constraint failed"
**原因**：外键约束违反，尝试插入引用了不存在实体的关系。

**解决**：
```bash
# 运行外键完整性检查
python src/validator.py --db db/medkb.db --report
# 检查报告的 "外键完整性检查" 部分
```

## 知识检索

### Q12: 查询返回空结果
**可能原因**：
1. 数据库路径不对
2. 知识库还未构建
3. 搜索关键词不匹配

**解决**：
```bash
# 1. 确认数据库存在且有内容
python src/query_engine.py --stats

# 2. 如果统计为0，先构建知识库
python src/kb_builder.py --from-structured

# 3. 尝试模糊搜索
python src/query_engine.py --search "阿司"  # 前缀模糊匹配
python src/query_engine.py --fulltext "疼痛"  # 全文搜索
```

### Q13: 药物相互作用查询只返回单向结果
**说明**：MedKB-AI会双向查询两个药品的相互作用关系。

```bash
# 同时查询A→B和B→A
python src/query_engine.py --interaction 阿司匹林 华法林
# 如果result中有"reverse_interaction"字段，说明双向都有记录
```

## 运行测试

### Q14: pytest找不到测试文件
**解决**：
```bash
# 从项目根目录运行
cd medkb-ai
pytest tests/ -v

# 或直接运行Python
python tests/test_quality.py
python tests/test_evaluation.py
```

### Q15: 测试报错 "ImportError: attempted relative import"
**原因**：直接从tests目录运行了测试文件。

**解决**：
```bash
# 从项目根目录运行
cd medkb-ai
python -m pytest tests/test_quality.py -v
# 或
python tests/test_quality.py  # 脚本会自动添加路径
```

## 性能优化

### Q16: LLM标注速度太慢
**优化建议**：
1. 使用更快的模型（如Claude Haiku用于初步标注，Sonnet用于质量审核）
2. 对长文档分段并行标注
3. 使用Mock模式进行流程调试

### Q17: 知识库查询变慢
**优化建议**：
1. 确保索引已创建（schema.sql中的CREATE INDEX语句）
2. 定期运行`VACUUM`清理SQLite碎片
3. 对于超大规模知识库，考虑迁移到PostgreSQL

## 数据恢复

### Q18: 误删了数据库
**恢复方法**：
```bash
# 重新构建（原始数据在data/目录中保留）
python src/kb_builder.py --from-structured
```

### Q19: 标注结果丢失
**恢复方法**：
```bash
# 重新运行标注流水线
python src/cleaner.py
python src/annotator.py
```

## 附录：快速诊断脚本

```bash
#!/bin/bash
# 运行此脚本快速诊断常见问题

echo "=== MedKB-AI 环境诊断 ==="

echo -n "Python版本: "
python --version

echo -n "项目根目录: "
pwd

echo -e "\n文件结构检查:"
for f in src/scraper.py src/cleaner.py src/annotator.py src/kb_builder.py src/validator.py src/query_engine.py; do
    if [ -f "$f" ]; then echo "  ✅ $f"; else echo "  ❌ $f 缺失"; fi
done

echo -e "\n数据文件检查:"
for f in data/raw/sample_drugs.json data/raw/sample_diseases.json db/schema.sql; do
    if [ -f "$f" ]; then echo "  ✅ $f"; else echo "  ❌ $f 缺失"; fi
done

echo -e "\n数据库检查:"
if [ -f "db/medkb.db" ]; then
    echo "  ✅ db/medkb.db 存在"
    python src/query_engine.py --stats 2>/dev/null || echo "  ⚠️  数据库查询失败"
else
    echo "  ⚠️  db/medkb.db 不存在（运行 kb_builder.py 创建）"
fi

echo -e "\n=== 诊断完成 ==="
```
